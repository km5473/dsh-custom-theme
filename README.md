# dsh-custom-theme · 外观全项自定义（0.4.5）

为 DeepSeek Harness Web / Desktop 制作的独立可自定义主题插件。出厂外观是青蓝与奶白的明暗双色，配一整张角色壁纸和六个卡通表情；而这套外观的每一项都可以改成你自己的。

> 0.3.0 之前叫 **dsh-vesna-theme（薇斯纳主题）**。改名后插件会自动接手旧名字下的设置与图片，不会重置你已经调好的外观。
>
> 0.4.5 把上游 dsh-vesna-theme 0.3.1–0.3.4 的聊天区玻璃效果并了进来（液态玻璃 / 高斯模糊切换、下拉列表配色修复），并新增发送框 3px 高斯模糊；随后把聊天框效果从「液态玻璃 / 高斯模糊」二选一**简化成一个高斯模糊开关**（液态玻璃已移除），并加了信息栏胶囊。

**壁纸、明暗两套配色、欢迎语、主题名称与描述、浅色/深色的名字、六个表情与它们的名字**全部可以自定义，并且可以**导出／导入配置文件**。

## 能自定义什么

设置 → 通用 → 卡片下方有三个折叠区：

| 折叠区 | 可改内容 |
| --- | --- |
| 配色自定义 | 浅色与深色各 19 个颜色项，**用十六进制色值（`#rrggbb`）直接改**，左边色块实时预览，右边是这一项的名字。最后三项是三个辅助色（**辅助色1 / 辅助色2 / 辅助色3**，出厂值分别是珊瑚粉、淡金、淡紫）。改过的项会高亮，可单项清除，也可整组恢复。 |
| 文案与名称 | 主题名称、主题描述、欢迎语（默认「找我什么事呀，亲爱的朋友~」）、**浅色名称**（默认「春日浅色」）与**深色名称**（默认「夜宴深色」）。留空即回到内置文案。 |
| 图片与表情 | 全窗口壁纸，以及六个表情槽位（比耶→新会话、思考→欢迎区、读书→文件入口、疑惑→负面评价、点赞→正面评价、爱心→发送）。每个槽位可单独选图、**单独改名字**、单独恢复默认。 |

卡片底部：**导出配置** / **导入配置** / **恢复默认配置**。自定义的名称会同时出现在配色分组的标题、明暗切换按钮和表情图库上。

### 聊天框效果

勾选「全窗口壁纸」后，卡片上多一行**聊天框效果**——一个开关：

- **高斯模糊**：用户气泡与模型回答换成静态模糊的玻璃面板，不做折射与高光，快速滚动更省渲染。**关掉开关**就恢复宿主原生面板（连同胶囊之外的玻璃一起让位）。
- **高级模糊**：再给每条消息卡片套一圈 **2px** 的高斯模糊边框——环里的模糊半径（10px）比卡片内部（3px）更大，所以卡片边缘会多出一层更柔的毛玻璃边。它模糊的是卡片背后的页面，所以同样跟着壁纸开关走；实现上把卡片自身的模糊挪到了 `::before`，否则卡片会变成 backdrop root，环就只能采到卡片自己的颜色。

同一区块里还顺带处理这三件事：

- **发送框 3px 高斯模糊**：输入卡保留 92%／95% 的近实色底，再叠一层 `blur(3px)`，壁纸在它下面被轻轻化开。
- **信息栏胶囊**：「N 轮 M 步 · x tok/s · 缓存命中 x%」那一行套上侧栏同色的胶囊底（`border-radius:999px` + 左右内边距）。底色用 `--dsw-alias-bg-module-platform`——palette 里 `sidebar` 的**实色**，会跟着设置卡片里改的侧栏色一起变；不能用 `--dsw-specific-sidebar-fill`，因为壁纸模式会把它抹成 transparent。纯装饰，不挂任何事件。
- **原生下拉列表配色**（上游 0.3.4）：Windows 的原生 `option` 列表不吃令牌层，深色下会白底白字，所以单独给 `select` / `option` 指定了背景与文字色。

关掉「全窗口壁纸」，或点「默认配色」，上述效果连同玻璃面板一起撤下，原生界面完全回来；系统开启「减少透明度 / 强制颜色」时它们也会自动让位。

### 十六进制配色

配色输入框接受 `#a1b2c3` 也接受 `a1b2c3`：

- 输入到第六位合法数字时立即生效，色块同步更新；
- 还没打完的中间状态会标出来，但**不会**写进设置；
- 失焦或回车时若仍不合法，就退回原来的颜色——所以打错字不会把颜色改坏。

## 配置文件

导出得到 `dsh-custom-theme-<时间>.json`：

```json
{
  "format": "dsh-custom-theme",
  "version": 1,
  "palette": { "light": { "accent": "#227c89" }, "dark": {} },
  "title": "", "description": "", "greeting": "找我什么事呀，亲爱的朋友~",
  "modeNames": { "light": "春日浅色", "dark": "夜宴深色" },
  "stickerNames": ["比耶", "", "", "", "", ""],
  "images": { "wallpaper": "data:image/webp;base64,...", "stickers": ["data:...", null, null, null, null, null] }
}
```

- 只写**自定义项**：图片是内嵌 data URL，所以一个文件就是一整套外观，换机器直接导入即可。
- 不写启用开关和明暗偏好——那些仍归 DSH 自己保存，导入配置不会把主题关掉。聊天框效果的选择也一样：它跟着启用开关走，不进配置文件。
- 导入是**全量替换**：文件里没有的图片会被清空。
- 校验失败（格式不对、版本不符、颜色非法、图片过大或不是图片）会拒绝整份文件并提示，**不会**改坏现有配置。
- 0.3.0 及更早导出的文件（`"format": "dsh-vesna-theme"`）仍然可以导入，名称部分按内置默认处理。
- 三个辅助色的键名现在是 `support1` / `support2` / `support3`（旧文件与旧记录里的 `pink` / `gold` / `lilac` 会被自动认领到对应项，导入导出都不会出错）；界面上显示的是「辅助色1 / 辅助色2 / 辅助色3」。

## 数据存放

| 内容 | 位置 |
| --- | --- |
| 启用开关、壁纸／表情开关、聊天框效果 | `localStorage` 键 `dsh-custom-theme.preference.v1` |
| 配色、文案与名称 | `localStorage` 键 `dsh-custom-theme.custom.v1` |
| 壁纸与表情图片 | IndexedDB 数据库 `dsh-custom-theme`，对象仓库 `assets` |

改名之前写在 `dsh-vesna-theme.*` 和旧 IndexedDB 库里的内容，会在首次读取时自动搬到新位置；搬完之后旧记录不再读取，但也不删除。聊天框效果现在是那个高斯模糊开关（0.4.5 起初是液态玻璃 / 高斯模糊二选一）：更早的记录里存的是 `material: 'liquid' | 'gaussian'`，两个值都折算成「开」，不需要手工迁移。

图片之所以不放 localStorage：内置素材本身就有约 3MB，再叠加自定义壁纸会撑爆 origin 配额，并连带把主题设置一起丢掉。上传的图片会先在 canvas 里缩放并重新编码（壁纸最长边 2560，表情最长边 320，优先 WebP 以保留透明通道），再存入 IndexedDB。**图片不会上传到任何服务器。**

## 安装

1. 从 Releases 下载 `dsh-custom-theme-0.4.5.tgz`（或在源码目录执行 `npm pack`）。
2. **设置 → 插件 → 添加插件**，选择该安装包，然后「立即启用」。
3. **重启 DSH**：插件清单是在启动时按包名组装的，改名必须重启才生效。
4. 重启后到 **设置 → 通用设置** 找到这张卡片。

从 `dsh-vesna-theme` 升级的话：装好新包、重启，确认外观无误后再把旧插件移除。配色选择、壁纸与表情开关、明暗偏好和自定义图片都会沿用。

## 卸载与恢复

- 临时恢复：卡片里点「默认配色」，撤下插件配色与壁纸、隐藏表情，原生明暗模式保留。
- 只清自定义：点「恢复默认配置」，配色、文案、名称、图片一起回到出厂状态，但主题仍是启用状态。
- 卸载：先「默认配色」，再到插件页禁用或移除 `dsh-custom-theme`，然后重新打开窗口。自定义记录留在本机，重新安装会沿用。

## 原理与边界

- 配色通过官方 `ThemeRuntime.overrideTokens(source, { light, dark })` 覆盖 `--dsw-alias-*` 令牌，插件不替换程序文件、不改 DOM 结构。
- 卡片用 `useSyncExternalStore` 读控制器的不可变快照，所有状态只有一份。
- 图片以 Blob URL 喂给 CSS，样式表里只出现短 URL，不会把几 MB 的 base64 反复写进 CSS。
- 欢迎语只改主页那一个已验证的标题文本节点，禁用或卸载时还原。
- 表情挂在原有按钮的伪元素上，按钮的文字、快捷键、禁用状态与事件处理都保留；恢复默认后原生图标自动回来。
- 选中标识符来自 CSS-module 的角色名（如 `sidebarCol`、`newSession`），与哈希无关；应用大版本升级后建议重新核对。
- **输入卡的模糊是刻意做小的**：它叠在整窗壁纸之上，悬停按钮触发卡片局部重绘时这层模糊要重新合成，在 Windows/Electron 上表现为会话区闪烁（上游 0.3.1 的修复）。所以它保留 92%／95% 的近实色底、只加 3px 的 `blur`，而不是大面积糊化；其余玻璃层（侧栏、顶栏、右栏 `blur(8px)`）照旧。原生那几个 `backdrop-filter` 读的是 `--dsw-menu-backdrop-filter`，本主题已把它设为 `none`。
- **信息栏胶囊只是一层皮肤**：把 `[data-composer-stats]` 那一行的圆角、左右内边距与底色换掉，不加滤镜、不加叠加层、不绑事件，所以它不会影响滚动性能，也不会碰到输入卡与旁边的上下文环。早期几版"底部渐隐模糊"（透明覆盖层 + `backdrop-filter`、对滚动容器加 `filter: blur()` + 双层蒙版、以及在输入条里插装饰层）都试过并已**全部移除**——这套布局里它们要么采不到正确的背景根，要么会糊到输入卡或信息栏文字。
- **聊天框玻璃挂在壁纸层上**：`data-dct-art`（壁纸开启）在，玻璃面板才生效；关掉壁纸或点「默认配色」就整层撤下。模型回答没有气泡外壳，用 `data-dct-assistant` 标记它现有的根节点，流式输出、复制按钮与选中都不受影响。
- 错误、警告、成功与差异配色不参与覆盖，保留平台语义。
- **停止按钮用强调色**：回合运行中，输入区那颗按钮会从「发送」变成「停止生成」——同一个元素，只换了标签。主题的令牌把它的填充色定成偏淡的 `raised`，所以运行中看着发灰；这条规则单独把该状态指到强调色（悬停用强调悬停色，图形用强调前景色）。它挂在 `body[data-dct-theme]` 上，跟着主题开关走，选「默认配色」时一切还原。

## 开发

```text
node scripts/build.mjs                  # 生成 lib/client.js（内嵌素材，无运行时依赖）
node tests/controller.test.mjs          # 状态、持久化、改名迁移与配置校验
node tests/plugin.smoke.mjs             # 打包产物：真实渲染设置卡片
node scripts/verify-served-bundle.mjs <已安装的 lib/client.js> [origin] [entry-id]
```

`plugin.smoke.mjs` 会用一个假的模块加载器把 `lib/client.js` 真正跑起来：解码内嵌素材、装配插件、渲染设置卡片的各种状态、检查卡片用到的每个文案键都存在于词典里，还要求**卡片渲染出的每个 class 在 card.css 里都有规则**（否则界面会静默掉样式）。**部署前请让它先通过。**

`verify-served-bundle.mjs` 复算宿主用来做缓存版本号的那串 sha1，再比对宿主实际返回的字节，因此「旧文件被当成新版」不可能蒙混过关。DSH 的网页服务需要启动时打印的带 token 链接才能打开首页，但插件包本身的路由不受影响，所以这个脚本不需要 token。

`node scripts/build.mjs <模块 id> <输出路径>` 可以把同一份代码构建成另一个模块 id，用于在改名过渡期让已启动的会话继续拿到新功能。

源码在 `src`，预构建产物在 `lib`，无新增 npm 依赖：

| 文件 | 职责 |
| --- | --- |
| `src/palette.js` | 出厂配色、颜色校验、令牌层构建 |
| `src/config.js` | 配置文件的构建与校验（纯函数，可测） |
| `src/controller.js` | 状态、持久化、改名迁移、图片、覆盖层 |
| `src/image-store.js` | IndexedDB 存取、跨库迁移、上传图片处理 |
| `src/art.js` | 壁纸／表情 CSS、按钮预览、欢迎语替换 |
| `src/glass.js` | 聊天框高斯模糊（含开关标记与标记扫描）、高级模糊环、发送框模糊、信息栏胶囊 |
| `src/client.js` | 设置卡片与插件装配 |
